# Point 10 — structured visual briefs and safe geometry DSL

`visualSpec.geometryRecipe`, facial components, apparel, accessories, and
decorative marks now accept a bounded declarative 2D geometry DSL. It is a
typed drawing format, not arbitrary SVG/XML and not a remote asset loader.

## Supported nodes and limits

- `path`, `group`, `ellipse`, `roundedRect`, `polygon`, `line`, and quadratic
  or cubic `curve`.
- SVG path data is limited to `M/L/H/V/C/S/Q/T/A/Z` commands, 256 command
  groups, finite bounded coordinates, and valid parameter arity. Scripts,
  event attributes, `<foreignObject>`, external references, and file access
  are not represented by the schema.
- A visual spec has at most 100 total nodes across its component lists,
  nesting is limited to four group levels, and node/transform/opacity,
  dimensions, palette, and gradient-stop values are bounded by the schema.
- Local linear gradients are implemented for closed-shape fills. Gradient
  stops are ordered and limited to eight; identifiers are generated by the
  renderer, and stops accept only solid hex colors and bounded opacity.
- SVG masks are not implemented and are intentionally not accepted or
  advertised. Existing face rendering still uses its internal static clip
  paths, not user-authored mask references.

## Reusable semantic geometry

`shared/geometry-library.mjs` supplies validated recipe builders for
`organicRound`, `taperedLimb`, `rigidBox`, `furniturePlane`, `curvedFood`,
`cylinder`, `fold`, `clothContour`, `leafStem`, `wheelSpokes`, `fabricLayers`,
`doorHinge`, and `expressiveFace`. The builders return ordinary geometry nodes;
the renderer remains generic, so combinations are assembled from the same
node vocabulary rather than per-component renderer branches.

```js
import {
  composeGeometryComponents,
} from "./shared/geometry-library.mjs";

const geometryRecipe = composeGeometryComponents([
  { name: "rigidBox", options: { rect: [-40, -25, 80, 50], cornerRadius: 5 } },
  { name: "wheelSpokes", options: { center: [0, 35], radius: 18, spokes: 8 } },
  { name: "expressiveFace", options: { center: [0, -5], radius: 16, expression: "smile" } },
]);
```

The registry is extensible by trusted application code through
`registerGeometryComponent(name, { schema, build })`; every produced node is
parsed again through the same strict `NodeSchema` before it can be composed
into a visual spec. User-provided data cannot register executable builders.

## Verification boundary

Focused tests validate DSL grammar, unsafe-input rejection, procedural recipe
composition, rendered SVG output, and legacy scene/plan behavior. A browser
raster smoke is still required for a visual pixel-level check; passing schema
tests alone does not establish visual quality. No provider response or live
provider request is involved in geometry rendering.
